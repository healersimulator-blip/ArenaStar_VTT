# Macros / FX Wizard — implementation status

Reference target: [`MACROS_FX_WIZARD_PARITY_SPEC.md`](MACROS_FX_WIZARD_PARITY_SPEC.md). **This is an integrated, incrementally verified implementation, not yet complete Sequencer/Tagger/MATT parity or a redefinition of that target.** The status below is intentionally stricter than “a type/editor field exists”: a criterion remains partial until its entire §10 scenario runs end to end.

## Working now

- **Named GM Revert for nonvisual world effects:** host-authored, bounded private action receipts record exact inverses and post-image hashes for tile traps, PF1e HP/temporary HP changes, chat, Tagger rules, roll applications, prefab placement, summon placement/dismissal and reviewed-script RPCs. A graph's later reviewed scripts/summons share its receipt; multiple successful RPCs form one action even if a later step fails. The GM's **Chat → World actions → Revert** restores an eligible completed action, including its graph history, in one host transaction; this is **not** merely visual FX cleanup or the latest global Undo. Pending workers and subsequently edited documents/dependents are refused, rather than overwriting another person's changes. Receipts survive compaction, reboot and world-file copies; players never receive them. Already-pruned chat entries obey the independent 100-message retention cap and are not resurrected, but do not prevent restoring unchanged mechanical effects. Client-originated edits and unrelated automatic lifecycle events are not retroactively associated with an action; pre-existing external effects cannot be unplayed. See [`e2e/action_revert.spec.ts`](e2e/action_revert.spec.ts) for GM wizard/trap, reviewed Worker and real connected-player click → GM Revert tests.
- **Hurt / Heal (bounded PF1e contract):** a fixed whole HP delta, negative for damage and positive for healing, applies to 1–32 selected linked-token actors with one application per actor. Temporary HP is spent first, healing updates PF1e nonlethal damage, and earlier changes in the same graph are read from staged actor state. Missing/malformed actor HP or a failed later graph step changes nothing. Dice/expression amounts, damage types and non-PF1e adapters remain **partial MATT parity**, not an implied feature ceiling.
- **One wizard window:** chat macros remain usable; GM tabs edit/import media timelines, search/compare up to six owned media files (image/video/audio previews) and send a selection into the current timeline, manage live persistent FX, review independently declared media sharing/export permissions, author active-zone graphs, tags, nested prefabs, summon presets and reviewed JavaScript macros. Players see only published script forms and may use authorized hotbar entries. Graph source/history, script source/grants/approval/return/trace and GM whispers stay private.
- **FX execution and lifecycle:** saved versioned image/alpha-video, text, sound and wait timeline sections; overlapping start times, layers below/above tokens but under fog, transforms/fades, host-resolved destination anchors, image stretching/tint and eased/repeated motion. **One-shot** image/video/text/sound sections can separately replay 2–8 times with a bounded pause between plays (not the same as movement cycles); the host expands at most 64 distinct clock-aligned cues inside the 60-second timeline, and reviewed `playAndWait` waits through the last play. A persistent loop cannot also use section replays. Source/target anchors use the token's **center**, and explicit follow bindings sample only a recipient's currently visible, projected tokens without per-frame socket traffic. GM or published player runs may create **private, host-owned persistent FX instances**; image/text/audio loops restore original host-clock phase after scene changes, reconnect and full reload. The Live FX tab lists/stops individual instances and lets a GM/assistant atomically stop up to 16 current-scene instances by a live name-glob/sequence/token filter in one undoable host transaction; the host rejects over-broad matches without partial stops. `api.fx.play`/`api.fx.stop` work in reviewed scripts, with the invoking player retaining ownership even when code runs under a GM grant. Reviewed `fx` scripts can now list entitled live instances with `api.fx.list({ name?, macroId?, sourceTokenId?, targetTokenId? })` and atomically stop up to 16 matches with `api.fx.stopMatching(filter)`. Names support bounded case-insensitive `*`/`?` wildcards; macro and token IDs match exactly; stop requires at least one explicit selector. A player running GM-elevated code still reads/stops only instances entitled to that actual caller, while an authorized GM can administer the scene. This is not the full Sequencer named effects/sounds API. Host deletion/undo, token/macro/scene deletion, visibility and media-entitlement changes stop/regrant exactly the affected recipients. Completed one-shot runs do not replay on reconnect/reload; replays occur only within the active run. Media bytes are imported by the GM, never bundled in the repository.
- **Tagger foundation:** typed embedded tags and legacy-flag reads, normalization, exact/case-sensitive default and opt-in any/exact-set, case-insensitive, substring, glob and bounded regex; scene/type/include/exclude queries with stable references, grouped results, a scene-invalidated index, a sidebar with quoted multi-term search, and atomic undoable bulk edits. The GM Tags explorer also has **Apply Tag Rules**: submit 1–32 exact scene-qualified refs, re-read existing `{#}`/`{id}` templates and hidden occupancy on the host, allocate per scene and commit one undoable batch; forged/player requests and any invalid target are rejected without a partial edit. A bounded recent request-ID cache avoids repeat allocation in the same host lifetime (not a durable restart guarantee). Reviewed-script tag reads now support explicit `{ sceneId }` and `{ allScenes: true, groupByScene: true }` across caller-visible scenes (including non-active scenes), bounded to 100 hits/16 KiB; `getTags(ref)` identifies the requested scene and `hasTags(ref, ...)` scopes it automatically. The host strictly validates ref shapes and reprojects from the **actual caller's fresh view on each RPC**; elevated player code cannot inspect hidden placeables or a private scene. GM-reviewed write helpers can now atomically edit up to 32 explicit placeable/scene refs **across caller-visible scenes** with live per-target permissions and undo; caller-run writes still require actual ownership, and no implicit all-scene write is allowed. `{#}`/`{id}` expansion is host-allocated scene-wide on prefab placement, with a shared per-instance ordinal and clone-specific graph reference rebinding, including nested Trigger Tile, Activate/Deactivate and targeted-variable IDs/tag filters plus collection selectors (dangling external targets fail placement).
- **Active tiles:** the GM can create a visible/hidden rotated rectangular tile directly in the Zones editor, publish a graph bound to it, and inspect/reset its bounded recent-fire history. Both GM and connected players can click visible tiles on the actual canvas; the request carries **a tile and hit point, never a private graph ID**. The host verifies scene, projection, rotated hit, owned selected token, replay ID and published player-click gate before resolving private graphs. GM-only graph/trace/history remain off player replicas. Other methods: host-observed committed movement enter/exit/stop/create/rotate and explicit GM manual; rotated rectangular swept hit testing; once-per-token, cooldown, chance, paused/max-run gates; triggering/inside/tile/tag selections. The editor lets GMs set a tile's integer trigger Sort when creating or editing it (players cannot change Sort). The editor now exposes **Shuffle Collection**, 1-based **Position in List**, scene-unit **Filter Tokens by Distance** (tile/trigger centers), bounded read-only **Filter by Attributes** (host-resolved direct/linked-actor paths, typed scalar comparisons or array membership), **Filter by Condition** (active effect names/PF1e condition labels and native actor condition names, with has/lacks), and **Filter by Items in Inventory** (trimmed case-insensitive item names, edge wildcards and typed item-*record* counts), plus **Filter by Token Trigger Count** on *each selected token* (live per-graph history, including this fire, unlike the triggering-token/user check) and **Check Data** on the triggering tile's staged typed attribute regardless of the current collection, with optional fail landing; filters can use a following Check Entity Count for branching, and an independent current triggering-token/user count filter includes this fire; named **Redirect Based on Method/Player Type**, lexical **Loop Through Entities** (nested/snapshot selection with `{{index}}`/`{{currentId}}`), a graph **Reset Tile Trigger History** action, **Set Active Tiles Current Collection** (add/remove/replace/clear), **Run All Batch Actions** (explicit tag/visibility/door queue flush), **Trigger Tile** (ID/current/tag targeting, token source, named child landing and optional Stop return), **Activate/Deactivate** (host-published paused gate on ID/current/tag-matched tile graphs, staged for a later Trigger Tile), and movement **Stop Additional Tiles Triggering**, alongside **bounded persistent graph-local tile variables** (assign/add to this graph or all graphs on scene-local ID/current/Tagger tiles, manual GM clear independent of trigger history, staged for same-plan child triggers and next-fire gates), existing run-local variables/value filters, escaped chat, landings/jumps/stop, tag edits, token/tile/pin show/hide, conditional-door state, sequence cues, **real saved-preset summon steps** and **reviewed script steps with declared literal/context-bound inputs**. Loop depth (8), collection size (1024), execution (up to 25,000 steps), world ops (1024), cues (256), and ordered post-commit script/summon actions (16) are explicitly bounded with errors rather than partial commits; nested graphs additionally cap at 8 depths, 32 tiles/tokens per call and 128 graph invocations. Outgoing loop jumps restore selection and context. A scene clone stages reads for parent and manual child graphs; every invoked graph records history once in the **same** preflighted atomic envelope, and cycles/missing landings fail before any world write. GM-only dry-run/trace and a 600-step acyclic graph are verified; cycles get a budget diagnostic and large trace delivery announces truncation. Mechanical graph ops and history commit in one envelope; FX follows success; queued script and summon actions run in authored order after the graph envelope, with separate authorized commits, bounded compendium resolution and GM-only failure diagnostics. A changed script approval hash is rejected **before** the graph transaction, while a post-commit Worker failure reports an explicit GM-only diagnostic without undoing earlier world actions. The ID-bearing graph request is **GM/assistant-only**: players cannot claim movement triggers, bypass the canvas hit with a guessed graph ID, or activate concealed tiles by guessing IDs.
- **World-clock action:** the Active Zones **Game Time** step advances or rewinds the replicated, host-owned clock by a fixed whole-minute amount (±525,600 minutes per step). The planner stages one coalesced settings op across a graph and its child tiles: later Check Value branches read the changed time, undo restores the clock and trigger history together, and a failed/dry-run graph changes neither. The GM authors the amount before publishing a player-click tile; players cannot patch world settings directly. Clock underflow/overflow and noncanonical settings overrides fail closed. Dynamic expressions, time-trigger scheduling and the rest of MATT's mechanics adapters are still open.
- **Approved programmable macros:** async JS runs in a disposable host-tab classic Worker (not in player tabs); GM-reviewed source+policy hash, caller/approved-GM action grants, bounded typed inputs, live visibility/authority and session checks on every RPC, nested calls with recursion/deadline/action budgets, reconnect replay marker, GM audit and player-redacted results. Scripts can query/edit tags with Tagger-style `getTags`/`hasTags`/`getByTag` and atomic bulk set/add/remove/toggle/clear helpers, send chat, play/list/stop matching FX, fire published automations, call other scripts and atomically place GM-reviewed prefab IDs via an explicit grant/allowlist. Reviewed Workers additionally expose `api.fx.playAndWait(id)` and a bounded `api.fx.sequence().play(...).parallel(...).playAndWait(...).wait(...).call(...).thenDo(...).run()` builder with ordered results. They await finite host-clock cue windows, not client decoding, and do not provide a global scheduler or an atomic transaction. `api.tags.applyTagRules(refs)` explicitly expands already-authored `{id}`/`{#}` templates in one undoable edit; scene-wide numbering is GM/assistant-caller-only because a player could infer the occupancy of hidden tags from skipped numbers. A separate pinned `summons` grant exposes `api.summons.place(presetId, x, y, summonerTokenId)` and `api.summons.dismiss(tokenId)`; player-callable GM-elevated code requires an exact approved preset allowlist, while all callers still pass live caster/scene/placement checks. These script actions commit separately and are **not** a transaction across the whole script. A world ZIP copy **or restore** invalidates imported script approval until the receiving GM re-reviews and republishes it. Workers are **not** hostile-code security sandboxes.
- **Summon lifecycle (partial SU-01–SU-08):** GM-indexed world actors and installed actor packs can be searched, toggled, filtered by source pack/PF1e CR and size, sorted, selected as a stable ref without placement, and saved as scene-bound private or player-published summon presets; a cancellable map crosshair previews footprint, grid, range and sight, while the host repeats authorization and placement checks. No source actor is permanently imported for a compendium placement. Each success atomically creates a **new linked actor+token**, owned by the actual caller rather than the elevated script, with its own bounded lifetime/instance marker; source media stays GM-only unless the owned hash is player-shareable. Dismissal, expiry, deleting either counterpart/scene, undo and reconnect preserve/clean exactly the intended instance. A published tile graph can invoke a private GM-authored preset on a player's authorized click/movement; source resolution after the graph commit is bounded and revision/caster rechecked, with failure disclosed only to the GM. The script worker can await a typed token result and dismiss only its caller's summons. **Not yet PF1e casting/resource/initiative rules, linked entrance/exit FX or an extensible per-system picker.**
- **Secrecy and media rights:** projected snapshots and updates retract/re-materialize hidden tokens, tiles and map pins; referenced media manifests and **each transferred chunk** follow current visibility and sharing consent. Private FX instances and GM-audience sequence macros never enter player snapshots or catch-up ops, and a revoked viewer receives only an opaque `fx.end`. Prefab instance, parent and source-scene flags stay host-only across creates, updates, scene-embedded-array updates, visibility grants and reconnect snapshots. GM-only graphs/code are absent from player replicas. Multiple writes to one object within a graph envelope now compute visibility crossings against the full pre-envelope state and deliver **one final create/delete**, so nested tag edits plus a hide/reveal cannot leave a stale token/tile on a player's replica. A deletion's pre-image is now used to project undo: a GM-only chat message ID is not sent to spectators, and mixed public/private undo envelopes no longer fail atomically on their replicas. The live Chat panel also refreshes on message **deletes**, not just creates/updates. World exports/imports preserve authored documents while imported JS loses authorization. FX uploads default to **GM-only playback and blocked world export**; the GM must separately attest player-serving and archive redistribution permission. Restricted FX blobs cancel ZIP/folder export rather than entering a half-valid archive. An imported world resets **both** FX rights declarations pending re-review. Legacy pre-wizard assets still need a broader rights migration/audit. Premium asset *platform integration* is not redistribution permission; no paid art is added to this repository.

## Try the integrated path

GM toolbar **Macros** → **Active zones**: expand **Create a rotated tile / zone in this scene**, enter its position/size and create it; choose the tile, enable **click** and optionally **Player click (published)**. Set **Trigger sort** (higher first on a tied movement crossing), change the initial selector to **Tokens in tile**, click **Add: forEach**, then use **Add inside loop** for a chat/tag/FX action (chat supports `{{index}}` and `{{currentId}}`). After the closing marker, add **filter → Tile trigger count** with optional maximum, **routeMethod** to a named **landing**, then save and optionally dry-run. For a relay, save a second **manual** graph on another tile, then add **collection → replace** (e.g. `This tile`) and **triggerTile** targeting that tile to the first graph; both graphs' world writes/history commit as a single undoable plan. Use **Add: Run All Batch Actions** after queued tag/visibility/door edits to execute that batch in order before subsequent steps; later changes to the same document form another batch, while the entire graph still commits or fails as one envelope. A child graph can start at a named landing. For an initially paused child, add **Set tile graph activity → Activate** for its tile immediately before **Trigger Tile**; the child sees the staged gate and the entire change undoes together. Tile visibility does not change, and a graph that deactivates itself completes its current fire. `{{originMethod}}` and `{{originTile}}` report the source event/tile in a child (while `{{method}}` is `manual`). Set the GM canvas layer to **Map** or **GM** to click it; a player clicks it directly in their canvas. Expand a saved zone's **Recent fires** for the last 100 invocations, or **Reset gates/history** to re-arm once/cooldown/max-run rules. **Add: set variable → Tile (persistent)** stores a bounded number/string/boolean value on the private graph (choose Assign or numeric Add; use the separate GM **Clear tile variables** button to erase the map). **Filter → Variable** reads staged changes in the same fire or the value carried over from the previous fire; graph actions and manual GM variable-clear share undo/history. Resetting gates does not erase these tile variables. Hidden tiles may respond to committed movement but are not clickable by players. Graph source, action list and trace never travel with the public tile-click request.

**World-clock branch:** In GM **Macros → Active zones**, add **Check Value → World-clock time of day**, choose `HH:MM` and a comparison/optional failure landing, then append a chat/action after each branch. The host reads the world's replicated settings, interprets 00:00–23:59 as minutes after midnight and wraps at each day boundary; it does not use the browser computer clock. GM **Settings → Advance clock** changes the committed time for the next fire. If the world clock has never been set, it is midnight; malformed stored clocks reject the whole plan. A connected player cannot directly write the clock or supply an event time; a GM-published tile can deliberately let them trigger a pre-authored Game Time change.

**Mechanical trap and script Revert path:** In GM **Macros → Active zones**, select a linked-token actor with PF1e HP, add **Hurt / Heal**, set a negative fixed integer, save a tile graph and fire it manually or publish a tile click to a connected player. The host spends temporary HP before HP; open **Chat → World actions** and press **Revert** on that specific trap to restore HP, temp HP, history and its message. Add a reviewed script step or run a saved reviewed script with world-writing Tagger/chat RPCs: the receipt groups committed writes (a failed later RPC leaves a marked partial action), and one Revert restores them without clearing the at-most-once script execution marker. No Revert during an active worker, and a subsequent actor/tag edit makes the affected action stale rather than silently erasing it.

**Game Time path:** In **Active zones**, place **Game Time → World clock change (minutes)** before **Check Value → World-clock time of day**. A value such as `90` advances the clock from 00:00 to 01:30 in the same graph; a later `-30` rewinds it to 01:00. Save and run or dry-run; Check Value, including in a manually triggered child tile, sees the staged time. Open GM **Settings** to see the replicated clock, and use **Undo** to restore the previous time together with the graph's message/history. Only fixed whole-minute amounts up to ±one year are supported; a negative clock, clock beyond 100 years or shadowing legacy settings document rejects the entire run, not just the clock step.

**Condition/inventory path:** GM **Macros → Active zones**: select **Tokens in tile** or a Tagger token collection, add **condition** (`Prone`, Has or Lacks) and/or **inventory** (`Potion*`, a numeric comparison and matching *item-record* count), then add **filter → Entity count** before a chat/tag/FX action. Names are trimmed and case-insensitive; `*` is allowed only at the start/end of inventory names. The host reads linked actors live even when the actor is GM-only; an unlinked token cannot pass Lacks or zero items. Filtering itself exposes no actor data to players, but the GM's downstream public actions can intentionally disclose the branch result. Other game systems' status registries, stack quantities, expression-based conditions and trigger sources remain open.

**Tile data and per-token history:** In **Active zones**, add **Check Data** to compare a safe path such as `width` on the *triggering tile* even if the current collection is empty; set a failure landing for an alternate branch. Add **Filter by Token Trigger Count** after selecting tokens, set comparison `= 1`, then add **filter → Current collection count** to branch on tokens on their first fire. Each token keeps a separate private history; Reset Tile Trigger History re-arms them and undo restores the previous counts.

**Summoning path:** GM **Macros → Summons** filters indexed world actors or installed packs by name/keyword, pack, size and available CR; **Select reference only** shows its JSON ref without a world import. Choose one, set scene/range/size/duration/LOS, and publish a safe preset (or keeps it GM-only). Use **Pick on map…** to preview/cancel/place. In **Active zones**, add a `summon` step, choose that saved preset and a tile/trigger/current anchor; enable player click if appropriate. The graph history commits once, and the real linked actor/token is independently created after the graph transaction by the host. In **Script macros**, enable the `summons` grant, check the exact preset allowlist for player-callable GM code, review the source+policy, and call `await api.summons.place(presetId, x, y, casterId)`; a second script call can `await api.summons.dismiss(tokenId)`. Typed token inputs are selected from visible scene tokens. The GM retains private source/control and receives post-commit traces; the player receives only a safe callable catalog and their own independent actor/instance. A script's multiple world actions are not atomic; a zone summon cannot roll back graph history if compendium resolution later fails.

**FX path:** GM **Macros → Assets / preview** filters owned image/video/audio files by name, MIME and hash, previews up to six side by side (≤20 MiB per preview), then **Use in timeline** assigns one to a section without copying the media. **FX timelines** authors a multi-lane cue, optionally selects source/target and **Follow visible token anchors**, marks it persistent, and runs it. **Live FX** lists host-owned instances and stops them without touching mechanics; authorized viewers regain an eligible aura after reconnect/reload. For uploaded media, the two separate sharing/export checkboxes default off; **Review existing media permissions** allows GM reapproval after a world import. ZIP/folder export refuses FX bytes lacking explicit redistribution rights. In **Script macros**, a reviewed `fx`-granted script can query `api.fx.list({ name: "ward*" })` and call `api.fx.stopMatching({ name: "Ward Loop" })`; all matching authorized persistent instances stop in one undoable envelope and reappear after undo. Alternatively, **Live FX → Stop matching live FX** accepts a scene, case-insensitive `*`/`?` name and/or exact saved sequence/source/target token IDs; an authorized GM/assistant stops up to 16 matching live instances atomically. The separate list search is only a preview, and a match over 16 is rejected without changes. For an executable chain, save short, nonpersistent timelines and use their saved IDs in a reviewed `fx`-granted script, e.g. `await api.fx.sequence().play("intro").parallel(api => api.fx.play("left"), api => api.fx.play("right")).playAndWait("outro").thenDo(api => api.chat.say("Done", "gm")).run()`. A cue must be scheduled to finish in ≤7 seconds (including host lead time) to be awaited; the Worker has a 10-second deadline. Earlier cues are **not** rolled back if a later section fails.

**Tagger rule path:** GM **Macros → Tags**: select up to 32 scene-qualified results with `{#}`/`{id}` templates already stored (use **Replace** to author them first), then click **Apply Tag Rules**. The host re-reads live hidden tags and allocates per-scene unique values in one undoable commit. The editing text field is not sent as a rule request. Players cannot invoke this GM-only allocation.

**Sequencer replay path:** GM **Macros → FX timelines**: add a text/image/sound one-shot, set **Section play count** to 3 and **Pause between plays ms** to 350, then save and run. This makes three separate clock-aligned plays of the same section; **Motion cycles** instead animates *within* one play. Persistent FX loops cannot also use section replays. A reviewed script may await the final play with `api.fx.sequence().playAndWait(id)`.

**Prefab path:** GM **Macros → Prefabs** captures scene objects and their linked tile graphs, chooses a root and a nested parent/lock for each child, previews bounds/media/reference failures, stamps two or more instances with fresh IDs and scene-unique `{#}`/`{id}` bindings, and lists/despawns entire instances. Token/tile root translation/uniform resize/rotation and root deletion atomically carry/cascade nested children and anchored graphs; undo restores all of them together. Hidden descendants and their media remain absent from player snapshots, reconnects and asset manifests. A GM-reviewed programmable macro may place an allowlisted template using `api.prefabs.place`, including a narrowly published player invocation. The prefab path still lacks **summons as prefab children, a full Sequencer programmable chain and sound/effect filters, non-token/tile root transforms, in-place attach/detach, and the complete MATT action registry**; this path does not satisfy full parity.

### Implemented MATT §5.4 action contracts (incremental)

All are **GM-published graph steps**, resolved on the host from a current event and live scene; players send no step payload. Each name below has a corresponding executable fixture in [`tests/core/automation.test.ts`](tests/core/automation.test.ts); [`tests/host/sync.test.ts`](tests/host/sync.test.ts) covers player movement, atomic update/projection and reconnect; [`e2e/active_zones.spec.ts`](e2e/active_zones.spec.ts) exercises the authoring controls in Chromium. Pure selection/route steps cause no world writes and need no undo entry; persistent writes use the existing atomic undoable graph envelope. Nested calls preserve this rule across parent and children, not as separate commits.

| MATT equivalent | Editor/definition contract | Runtime and authority/undo contract |
| --- | --- | --- |
| Activate/Deactivate | `setActive.mode: activate\|deactivate\|toggle` with scene-local ID/current/Tagger tile targeting | Alters only the private published graph's paused gate, never tile visibility; up to 32 tiles/128 distinct graph edits. Subsequent nested Trigger Tile calls see staged changes; self-deactivation does not cancel the approved current run/post-commit actions. All changes and child history share one preflighted envelope/undo; disconnected/forged players receive no graph IDs. |
| Set Active Tiles Current Collection | `collection.mode: add\|remove\|replace\|clear`, with a scene-local selector except on clear | Stable ref-identity deduplication; add/remove/replace/clear the current graph's targets with staged Tagger matches. Collection changes alone write no world ops. Owner/user collections and inter-graph collection returns remain open. |
| Set Active Tiles Variable | `set.name` with `scope: tile`, `operation: assign\|add`, bounded literal number/string/boolean value and optional `target: id\|current\|tag` (self graph if absent; no expression evaluator yet) | Each graph has a private durable map (≤64 keys; identifier names; bounded values) in its existing state; arithmetic is finite and reads the **persistent** value even if a run-local variable has the same name. Up to 32 same-scene tiles / 128 graph states per plan; each graph bound to a target tile receives its own value, including paused graphs, without incrementing its trigger count. Staged writes feed later child Trigger Tile calls; the current graph's own writes feed filters/chat. All state/history and mechanics share one preflighted undoable envelope. GM **Clear tile variables** clears the map without resetting gates; history reset preserves it. No player can read/edit the map directly. Dynamic handlebar names/values, wildcard updates, delete, scene/global/user variables and other external tiles remain open. |
| Run All Batch Actions | `batchFlush` action in the graph/inside a child or loop; no parameters | Executes the currently queued tag, visibility and door writes **at that graph position**: combines writes to each target into one update per batch, appends the updates before subsequent ops, advances baselines, clears the queue, and starts a new batch for later actions. Child graphs share the queue. The final queue flushes implicitly. Host publication, projection and undo remain **one atomic envelope** even across explicit barriers; runtime/preflight failure discards all batches. Other MATT batch-action families are not yet supported. |
| Trigger Tile | `triggerTile.target: id\|current\|tag`, token source `triggering\|current\|inside`, optional child landing and `propagateStop` | Finds **manual-method, same-scene** GM-authored graphs by target tile on the host. Stage an active-scene copy; parent/child tag and door edits feed later selectors; coalesce repeated histories and per-batch writes into ONE undoable envelope. Depth ≤8, tile/token fanout ≤32 each, graph invocations ≤128, steps ≤25,000, ops ≤1024, cues ≤256, scripts ≤16; cycles, missing target/landing and preflight failures discard the entire world plan. FX/scripts retain their explicit post-commit contracts. No arbitrary cross-scene child ID is accepted from a player. |
| Stop Additional Tiles Triggering | `stopOthers` action | After a successful movement graph commit, suppress later tiles for that same moving token (path fraction, method, descending optional tile `sort`, then IDs). A skipped/failed/dry-run graph does not suppress; a separately clicked tile is the only tile currently dispatched for click. This is not the full MATT overlap/priority algorithm. |
| Shuffle Collection | `shuffle` action on current collection | Host Fisher–Yates RNG; stable dry-run seed; no write/undo. |
| Position in the List | `position.index` (integer, 1-based, 1–10,000) | Keeps that single current target or none; no write/undo. |
| Filter Tokens by Distance | `distance.from: tile\|trigger`, `min?`/`max` in finite scene units | Centers + `scene.grid.distance / size`; rejects missing trigger/non-token targets; no write/undo. |
| Filter by Attributes | `attributes.path` with exact `eq/ne/gt/gte/lt/lte/has` and typed scalar value; `name`/geometry/door etc., own-data `system.*`/`flags.*`, linked-token `actor.system.*`/`actor.flags.*`/name | Filters current token/tile/wall/drawing collection in order; missing/mismatched paths do not match even for `ne`; numeric order only, `has` only for arrays (not template/JS expressions). Host reads staged placeables and live linked actors, not the requesting player's graph payload. No world write; a following count check branches. Path depth ≤8, value ≤256 characters, leaf ≤4096 chars/elements and ≤100,000 comparisons across the nested plan; oversized/unsupported inputs fail without partial commits. GM-only graph and trace are not projected to players. |
| Check Data | `checkData.path` is a tile-only bounded own-data path with typed `eq/ne/gt/gte/lt/lte/has` and optional named failure landing | Compares the **triggering tile**, never the current collection, using the staged scene clone and shared bounded read budget; failure stops or jumps without disclosing private tile attributes to players. Core/host/production Chromium fixtures. |
