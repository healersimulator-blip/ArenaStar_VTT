## Findings

### 1. [P1] Roll evaluation always falls back to zero inside the actual AIS sandbox

**Location:** `modules/ais-foundry-v13/runtime/adapter.js:1337–1345`  
**Introduced:** `28d6716`

Both evaluator branches use `Function(...)`. The actual iframe CSP in `src/packages/aisModuleIframe.ts:441` permits inline/blob scripts but deliberately does **not** permit `unsafe-eval`. Consequently even `new Roll("2+3").evaluate()` fails code generation, catches the failure, and reports total `0`; dice are generated but their resulting arithmetic expression also evaluates to zero. This breaks the new Roll compatibility surface for modules using it and hides the failure as a successful evaluated roll.

**Evidence:** extracted the exact Roll class into a Node VM with string code generation disabled; `2+3` returned `0`. This is a focused reproduction of the prohibited operation, not a full browser run.

**Fix:** implement arithmetic parsing without dynamic code generation; keep the CSP intact. Add a browser test in the real AIS iframe for constant arithmetic and dice totals.

### 2. [P1] LevelDB conversion ignores live-version and deletion semantics

**Location:** `src/packages/packageLoader.ts:476–499` (also the SST entry loop above it)  
**Introduced:** `28d6716`

The importer collects JSON values from every matching file and retains the first occurrence of each `_id`. It never interprets the LevelDB internal-key sequence/type, live file set from CURRENT/MANIFEST, deletion tombstones, or write-batch records. An ordinary uncompacted database can contain old and current versions of a document across tables/logs. Import order can therefore select stale data, and a deleted document can be resurrected because its JSON value is retained while its tombstone is ignored. Successfully extracting JSON is not equivalent to reading a LevelDB snapshot.

**Evidence:** static review of the SST reader and first-ID-wins deduplication. No real multi-version upstream database was available for an integration reproduction.

**Fix:** use a proven snapshot/export path or implement live-file, sequence, tombstone, and WAL handling. Until then reject unsupported database layouts rather than silently treating a best-effort scan as authoritative content. Test updates and deletes spanning SST/WAL files.

### 3. [P1] Fireball/revert acceptance asserts canned answers, not PF1 gameplay

**Location:** `modules/ais-foundry-v13/runtime/adapter.js:2254–2260`; `e2e/real_pf1_fireball.spec.ts:72–87,103–115`  
**Introduced:** `88222a6`

The production adapter's test helper assigns `casterLevel = 5`, `fireballDice = "5d6"`, and `correct = true` directly. The test compares those constants to identical constants. It never loads the Fireball document's damage calculation, casts it, rolls damage, targets an Ogre, applies damage/saves, or reverts the resulting AIS action. The final `actionLog` locator is never asserted or used. Even actor creation success (`wizardFound`) is not asserted. The Ogre search accepts any name containing “ogre,” including a feat such as Ogre Crush.

This acceptance can pass with broken roll evaluation or AIS action/revert integration. Existing native `action_revert.spec.ts` coverage does not prove the newly added AIS attribution path.

**Fix:** move test helpers out of the generic production adapter and exercise the real spell/actor/module API. Assert a persisted target-state change, receipt attribution, and actual restoration through GM revert. Keep the current content-name lookup only as a separately named boot/index smoke test.

### 4. [P2] Nested-root distributions silently skip LevelDB pack conversion

**Location:** `src/packages/packageLoader.ts:462–470,518–523`  
**Introduced:** `28d6716`

Conversion happens before archive rooting. For `release/module.json` declaring `packs/items`, the binary map contains `release/packs/items/000001.ldb`, but the matching prefix is just `packs/items/`. No binary matches; the package still imports, without a synthetic pack resource. Root stripping later cannot recover the skipped content. Nested release/GitHub archives are an explicitly supported import shape.

**Evidence:** a temporary test passed the same minimal binary fixture through `readZipPackage` at root and under `release/`. The root archive produced `packs/items/_converted.db`; the nested archive imported successfully but produced no converted resource.

**Fix:** normalize text and binary paths into the same package-root coordinate system before conversion, then emit resources in that same coordinate system. Account for system manifests under `public/` separately from an outer release folder.

### 5. [P2] PF1 workaround disables strict choice validation for unrelated DataModels

**Location:** `modules/ais-foundry-v13/runtime/fields.js:469–477`  
**Introduced:** `3477ebf`

The leniency check accepts any validation failure containing `is not a valid value`, regardless of model class or field. This is the generic error for a choice/enum mismatch, not a PF1 Condition-specific signature. Strict models from any module now accept invalid values and proceed to initialization, invalidating their schema contract.

**Evidence:** the existing `aisFoundryCore.test.ts:330` regression test fails: constructing `Prefs({ mode: "medium" })` no longer throws for the declared choices.

**Fix:** preserve strict validation by default; address the specific PF1 schema incompatibility or explicitly scope an opt-in compatibility exception to the intended model/field.

### 6. [P2] World-pack `index` getter throws before index hydration

**Location:** `modules/ais-foundry-v13/runtime/adapter.js:177–182`  
**Introduced:** getter in `b780ea8`, collection in `adbab37`

World compendia initialize `_index` to `null` and are installed into `game.packs` without calling `getIndex`. Reading the newly implemented `pack.index.size` therefore calls `.map` on null. This is precisely the synchronous index-inspection surface the PR says it supports. Additionally, the fields-requesting `getIndex` branch returns its results without updating `_index`, so even that successful hydration does not make the getter safe.

**Evidence:** extracted the exact class and confirmed a newly constructed pack throws on `.index.size`.

**Fix:** start with an empty Collection and maintain it during all successful index fetches. Test access before loading, after a plain fetch, and after a fields-requesting fetch.

### 7. [P2] The merged PR fails the project's typecheck gate

**Location:** e.g. `src/packages/foundryEsmGraph.ts:401–402`, `src/core/foundryModuleManifest.ts:264`, `src/packages/packageLoader.ts:503–505`, and new E2E files  
**Introduced:** multiple commits in this PR

`npm run typecheck` exits unsuccessfully with **25 TypeScript errors**. Production errors include indexing with `BARE_SHIMS.fuzzysort` typed as possibly undefined under `noUncheckedIndexedAccess`, and unused `sysCandidates`, `syntheticPath`, and `finalPath`. The new tests also contain implicit-any parameters, unused variables, and unchecked array accesses. Since the command uses `tsc --noEmit && ...`, Svelte checking is never reached.

**Fix:** correct the new types/dead declarations and type the Playwright helpers/array accesses; rerun the full typecheck rather than relying on the earlier commit's passing result.
